# SpecFlow Engineering Studio v0.9.2

> 本次小版本修复引用阅读器空白问题，并重做 DeepSeek Harness 的语义检索、追问和原文跳转链路。

## PDF 引用阅读器

- PDF、界面资源和 Range 响应显式使用 `no-store`，避免重新解析或替换文件后继续读取陈旧缓存；
- 每次引用跳转都有独立加载代次，快速连续点击时旧请求不会覆盖新请求；
- 打开引用后立即显示加载状态，不再以空白区域代替处理中状态；
- 检查 HTTP 状态和 PDF 字节长度，失败时显示原因并提供“重新加载”；
- 关闭阅读器时取消尚未完成的渲染和文档任务。

## DeepSeek Harness 集成

- `specflow_search` 的每个命中都返回绝对 `sourceUrl` 和可直接复用的 Markdown `markdownLink`；
- 从 Harness 点击链接时，通过本机 HTTP 桥接激活已经打开的 SpecFlow 桌面窗口，跳转到对应页并高亮原文；
- 同时保留 `rawSourceUrl`，供 Agent 或其它系统直接读取原 PDF；
- 设置页比较已安装组件和当前内置组件版本；检测到本机仍使用旧版（例如 0.7.1）时，明确提示更新并重启 Harness；
- 不修改 DeepSeek Harness Studio 源码。

## 语义查询规划与必要追问

- SpecFlow 在检索前统一生成 `queryPlan`，Harness 和独立客户端共享相同逻辑；
- 支持把“综合楼 / complex building”扩展为“民用建筑群、民用建筑、公共建筑、建筑群、多功能组合建筑”；
- 把“消防间距”扩展为“防火间距”，并把“火灾危险性分类”关联到生产、储存危险性类别及建筑分类；
- 当综合楼用途、高度、生产储存内容或相邻建筑条件不足时，返回 `clarify_user` / `mode=clarification`，先追问再检索，不直接生成武断的工程结论；
- 对话补充信息会和原问题一起重新规划检索。

## 验证与兼容

- 77 项自动化测试全部通过；覆盖语义扩展、追问阻断、桌面引用唤醒、PDF 禁用缓存、Harness 旧组件检测和引用链接结构；
- 文档、索引、分组、对话、工程项目和模型设置保持兼容；
- 安装 v0.9.2 后需要在“设置 → Harness 连接”点击“更新至 0.9.2”，然后完全退出并重启 Harness，新的 Agent 工具逻辑才会加载。
